The emitted deltas have caller debt/credit signs: negative input, positive output. Pool.swap accumulates positive output and subtracts the consumed exact-input amount; PoolManager emits that BalanceDelta, then applies the hook's adjustment and accounts the final caller delta. DeltaResolver negates negative debt for settlement and takes positive credit. The interface's short description of a pool balance delta is insufficient to infer the sign. [Pool arithmetic](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/libraries/Pool.sol#L373), [delta orientation](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/libraries/Pool.sol#L452)

| zeroForOne | amount0 | amount1 | Executed pool input | Executed pool output |
| --- | --- | --- | --- | --- |
| true | negative | positive | -amount0 | amount1 |
| false | positive | negative | -amount1 | amount0 |
| either | reversed signs or zero | reversed signs or zero | Refuse native inference | Refuse native inference |

PoolManager emits Swap before afterSwap. For exact input, AFTER_SWAP_RETURNS_DELTA adjusts the unspecified output; BEFORE_SWAP_RETURNS_DELTA can adjust either leg. The sampled hook mask 0x2044 means BEFORE_INITIALIZE, AFTER_SWAP and AFTER_SWAP_RETURNS_DELTA. [Emission ordering](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/PoolManager.sol#L198), [hook adjustment](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/libraries/Hooks.sol#L284)

ERC-6909 Transfer events represent claims, transfers, minting and burning, and cannot evidence an ETH payment or refund. This is why a direct hooked native output remains pending. ### Changes and ownership decisions

Base's three bundled endpoints now declare one requestPacingGroup with 250 ms between starts. That is four starts per second across the lane, below the documented fallback ceiling. Chain-ID verification, independent read clients, failovers and pinned clients share the same admission owner. Other chains and personal endpoints keep their declared policies. Pacing bounds starts rather than response duration; it does not coalesce reads, add retries, or guarantee a provider will answer under external load. It intentionally adds latency to a public-lane quote in exchange for keeping the execute viable. Concurrent first requests now share one transport initialization and endpoint choice.

The execute reuses token metadata it has just resolved for its initial comparison. Before signing it still reads decimals and runs a fresh quoter call. quoteFreshV4Pool accepts only the binding carried by this execution, checks deployment/version, pool ID, full PoolKey hash, direction and hook permission equality against approval, and avoids a second poolKeys/getSlot0 pair. No binding from a previous execution or approval wait is used as fresh. The initial execution read supplies observed lpFee; the final live quote remains authoritative for refusing output below the approved minimum. No general RPC result cache was introduced.

The estimate now receives the same address rather than the local signer object, preventing viem from preparing nonce and fees inside estimateGas. Gas is explicitly estimated; preparation then fills only chainId, nonce and type when approved fees are already supplied. This removes the two optional fillTransaction requests and the duplicate nonce/block/tip reads. The final nonce read/reservation, fee-cap check, fresh balance read, output-floor check and distinct L1 fee calculations remain. No eth_feeHistory calls occurred in this checkout's measured path. Native source/native debit already share one balance observation, so no balance proof was removed.

### Typed refusal and ledger contract

RpcReadExhaustedError is created at the transport boundary after the selected read lane cannot answer. It carries chain ID, method and the existing RpcFailureClass, without embedding a provider dump in its message. Contract reverts keep their original path; caller cancellation keeps AbortError identity; timeouts remain transport failures. Broadcast methods are never branded as pre-sign reads. Unknown node responses carrying a recognized contract error retain that stronger decoded evidence.

Both venues now return status=not_attempted, retryable=true, the RPC failureCode and an authored reason for pre-sign exhaustion, before or after intent creation. The reason names the chain, says no signature/broadcast occurred for this step and directs the user to wait/re-quote or Settings > Chain endpoints > EVM RPC URL, backed by localChainRpcUrls. The actual UI and persistence handler were read before writing that instruction. Price-cap wrappers retain a nested RPC cause rather than hiding it. Metadata, balance, gas and L1 fee helpers propagate typed exhaustion instead of flattening it to a token error or an unpriced fee. KyberSwap's staged/broadcast guard remains decisive: an error after hash staging stays pending, never a safe-retry refusal.
