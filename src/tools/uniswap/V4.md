## Readiness

Not ready for unrestricted execution sign-off. The implementation is testable and the read-only live quotes passed. The existing Robinhood Ordofi fallback was measured to support callTracer; the probed Base endpoints did not return a usable trace. ## Scope and design

Exact-input single-hop candidates join the existing tool pair. V2 and V3 keep their existing routers. V4 uses the verified UniversalRouter version and transaction-based Permit2 allowances. No SDK dependency is added. The alternative, moving all versions onto UniversalRouter, is rejected because it changes two established signing paths without need. Mixed routes, exact output, liquidity operations, arbitrary hookData, signed Permit2 permits, and undiscovered pools are outside this arc.

### Deviations and remaining risks

- Net-of-gas ranking is implemented when every successful candidate has quoted gas and a usable output/native conversion. A successful V2 route lacks a quoter gas figure, so selection explicitly reports gross_output_gas_comparison_unavailable. Quotes never invent a V2 gas constant. Full net-of-gas selection across all V2/V3/V4 candidates remains incomplete. Quoted gas also excludes allowance transactions; actual plan costs are measured after route selection.
- Native input/output settlement requires an executed call trace to account for refunds and hooks. The existing Robinhood Ordofi endpoint returned one. Official Robinhood and PublicNode do not expose the method. Base official and developer endpoints do not expose it; Tenderly returned a limit error. Without a usable trace, a confirmed native swap keeps confirmed_pending_amounts, never guessed amounts. Configure a trace-capable Base RPC before expecting the execute-stage settlement assertion to pass. Native output reporting remains omitted under the existing AgentScan verification policy. A refunded native input is likewise omitted from AgentScan executed input because that server checks gross tx.value, not net refunds.
- AgentScan's existing event enum accepts Uniswap swaps independently of pool version, so no activity-role or reporting vocabulary widening is needed. Permit2 approvals remain the existing allowance activity role, with allowanceKind=permit2 in local provenance; the cost plan uses a distinct permit2_allowance role. The server still needs the supplied companion patch to retain route metadata. Its database migration and server integration checks have not been run; only clean application and the real patched contract parser were checked. Deploy its reader before this writer.
- The execute live stage was deliberately never run. No owner credentials, key material or signed transaction payloads were printed. The gated stage exercises the actual runtime approval binding, inventory keystore path, settlement, fee disposition and database activity. It uses the native tiny amount 0.0001 ETH on each chain, below both requested caps.
- New behavior is covered by tests that import and exercise new v4 functionality absent in the old tree. No destructive mutation or temporary rollback of the working implementation was used to run an old-code mutation experiment.
