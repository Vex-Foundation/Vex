# Direct Uniswap v4 implementation record

## Readiness

Turn 2 removes the call-trace dependency. The decoder uses a unique PoolManager Swap event bound to the approved pool ID and UniversalRouter, wallet ERC-20 Transfer deltas, and ordinary transaction from/to/value facts. Base no longer needs a trace-capable RPC for a full-fill native-input swap or a native-output swap whose native amount is not changed by a returns-delta hook. The old trace module was removed after a repository-wide consumer check.

Some native amounts remain deliberately pending: a direct native output that a returns-delta hook may adjust has no payment log, and a direct native input with an unexplained transaction-value difference has no observable refund amount. These are missing receipt evidence, not missing trace-provider prerequisites. Wrapped legs can use router-bound WETH Deposit/Withdrawal logs, including an observed wrapper refund. No pool estimate replaces the wallet's ERC-20 Transfer truth.

V2 candidates now receive fresh eth_estimateGas estimates of their built router calls from the selected wallet in both restricted and full sessions. No wallet, an unavailable estimate, or an unavailable native/output conversion keeps the explicit gross_output_gas_comparison_unavailable label. No constant gas figure is invented. V3 and V4 retain their quoter figures. The remaining full-tree type-ratchet failure is pre-existing: the same 81 excess fingerprints reproduce in pre-v4 commit c8be521a2e85f24a715d82dcdf495dd3ed82997d. No new diagnostics remain, but the stored ratchet baseline has not been reached. The baseline file is unchanged.

The AgentScan companion server patch from the checkpoint still needs its independent server rollout before the server retains route metadata. No live execution has been run.

## Scope and design

Exact-input single-hop candidates join uniswap__swap_quote and uniswap__swap_execute. V2 and V3 keep Router02 and SwapRouter02; v4 uses the recorded UniversalRouter version and transaction-based Permit2 allowances. SDKs are references only; production encoding uses installed viem 2.54.3. Mixed routes, exact output, liquidity operations, arbitrary hookData and signed Permit2 permits are outside this arc.

## Pin notes and sign convention

The periphery checkout has an unpopulated lib/v4-core submodule. Both its gitlink and foundry.lock pin 59d3ecf53afa9264a16bba0e38f4c5d2231f80bc. The exact pinned source was retrieved from the first-party repository into /tmp/vex-v4-core-reference without modifying the reference checkout. Also read periphery V4Router.sol and base/DeltaResolver.sol.

The actual event ends in int24 tick, uint24 fee. The proposed fee-before-tick order would produce a different topic. toEventSelector on the pinned signature gives 0x40e9cecb9f5f1f1c5b9c97dec2917b7ee92e57ba5563708daca94dd84ad7112f, verified against the real receipt fixture. [Pinned IPoolManager event](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/interfaces/IPoolManager.sol#L91)

The emitted deltas have caller debt/credit signs: negative input, positive output. Pool.swap accumulates positive output and subtracts the consumed exact-input amount; PoolManager emits that BalanceDelta, then applies the hook's adjustment and accounts the final caller delta. DeltaResolver negates negative debt for settlement and takes positive credit. The interface's short description of a pool balance delta is insufficient to infer the sign. [Pool arithmetic](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/libraries/Pool.sol#L373), [delta orientation](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/libraries/Pool.sol#L452)

| zeroForOne | amount0 | amount1 | Executed pool input | Executed pool output |
| --- | --- | --- | --- | --- |
| true | negative | positive | -amount0 | amount1 |
| false | positive | negative | -amount1 | amount0 |
| either | reversed signs or zero | reversed signs or zero | Refuse native inference | Refuse native inference |

PoolManager emits Swap before afterSwap. For exact input, AFTER_SWAP_RETURNS_DELTA adjusts the unspecified output; BEFORE_SWAP_RETURNS_DELTA can adjust either leg. The sampled hook mask 0x2044 means BEFORE_INITIALIZE, AFTER_SWAP and AFTER_SWAP_RETURNS_DELTA. [Emission ordering](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/PoolManager.sol#L198), [hook adjustment](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/libraries/Hooks.sol#L284)

TAKE/TAKE_ALL pay the router's credit to the bound recipient. PoolManager.take updates transient accounting and calls Currency.transfer; neither emits a native-payment log. ERC-6909 Transfer events represent claims, transfers, minting and burning, and cannot evidence an ETH payment or refund. This is why a direct hooked native output remains pending. [take](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/PoolManager.sol#L291), [native transfer](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/types/Currency.sol#L40), [ERC-6909 claims](https://github.com/Uniswap/v4-core/blob/59d3ecf53afa9264a16bba0e38f4c5d2231f80bc/src/ERC6909.sol#L79)

Viem's nested tuple encoding is pinned by the SDK 2.0 USDC/WETH vector at v4Planner.test.ts:74-88, settlement vectors at 392-420 and take vectors at 426-445. The 2.1.1 single-hop tuple is also compared with the already-installed independent ethers ABI coder. Production never imports an SDK. Pool ID hashing matched the live PositionManager key. The non-view quoter uses eth_call through simulateContract. Permit2 allowance is (uint160 amount,uint48 expiration,uint48 nonce), and approve encodes uint160 amount and uint48 expiration explicitly.
